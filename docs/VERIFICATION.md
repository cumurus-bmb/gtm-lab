# 検証ガイド — GTM Preview / GA4 DebugView / 採点パネル

GTMでタグを組んだら、「多分動いてる」で終わらせず、3つの独立したツールで裏取りする。3つとも見ている層が違うので、どれか1つだけでは足りない。

| ツール | 見ているもの | 答えてくれる問い |
|---|---|---|
| **GTM Preview（Tag Assistant）** | 現在のドラフト設定：どのトリガーが発火し、どのタグが動き、変数が何を解決したか | 「設計上、これは発火**すべき**か？」 |
| **GA4 DebugView** | Googleのサーバーに実際に届いたイベント（リアルタイム） | 「GA4側にちゃんと着地しているか？」 |
| **採点パネル（このプロジェクト独自）** | ブラウザが実際に送信したネットワークの生データ（`/g/collect`） | 「この課題の合否基準を満たしているか？」（ground truth） |

## 推奨の検証順序

毎回3つ全部を律儀にやる必要はないが、詰まったときは基本この順で切り分けると原因を絞りやすい。

1. **GTM Preview** — トリガー条件・変数の値・タグの発火有無を設計時点で確認する。ここでNGなら、まだGA4にもLabGraderにも届いていないので、GTM側の設定ミス（トリガー条件、セレクタ、変数）を疑う。
2. **GA4 DebugView** — Previewで発火が確認できたら、実際にGoogleのサーバーまで届いているかをDebugViewで見る。ここで見えない場合、送信先の設定（測定ID、ネットワーク到達性、DebugViewへの`debug_mode`付与漏れなど）を疑う。
3. **採点パネル** — 最後に、このラボの各課題が定義する合否条件（パラメータ名・型・発火回数・タイミング）を機械的に満たしているかを見る。PreviewやDebugViewで「見た目は動いている」ように見えても、パラメータ名のtypo（`ep.item_id`のつもりが`ep.itemId`など）や値の型（文字列 vs 数値）で採点パネルはFAILになる。**この採点パネルの判定が、このラボにおける最終的な正解**。

## 1. GTM Preview（Tag Assistant）

1. GTMのワークスペースで「プレビュー」ボタンを押す。
2. 接続先URLに `http://localhost:8080/`（docker composeで起動したサイト）を入力して接続する。
3. 接続すると別タブでサイトが開き、画面右下に緑〜青系のTag Assistantデバッグウィジェットが出る。
4. サイト上で対象の操作（クリック、フォーム送信、スクロールなど）を行い、Tag AssistantのSummaryで「発火したタグ」「発火しなかったタグ」を確認する。
5. 各タグをクリックすると、そのタグに渡った変数の値（イベント名、パラメータ）が見える。ここで期待通りの値が入っているかをまず確認する。

Preview中はGA4への送信に自動的にデバッグ用の情報が付与され、後述のGA4 DebugViewにもそのまま連動する（別途の設定は不要）。

## 2. GA4 DebugView

### Preview接続中なら基本は自動

GTM Previewで接続しているタブからの送信は、GTMが自動的にデバッグ扱いにしてGA4へ送るため、GA4管理画面の「DebugView」を開くだけで、そのタブでの操作がほぼリアルタイムで表示される。`localhost`だから特別な設定がいる、ということは通常ない——Previewセッションが有効な間は意識しなくてよい。

### Preview接続なしで`debug_mode`を送りたい場合

公開済み（本番）コンテナの動作確認など、GTM Previewを使わずに`debug_mode`を付けたいケースでは、以下のいずれかで対応する。

- **タグ側でイベントパラメータとして追加する**：GA4イベントタグのパラメータに `debug_mode` = `true` を追加する。これは送信時に `ep.debug_mode=true` としてヒットに乗る。採点パネルのHit Logはこれを `hit.params.debug_mode` として解釈するので（`ep.`プレフィックスを剥がして`params`に格納するロジック — `site/assets/lab-grader.js`）、GA4 DebugViewだけでなくこのラボの採点パネルのHit Logでも同じ値が確認できる。
- **GTM側の「デバッグモード」用チェックボックス／変数を使う**：GA4イベントタグ（バージョンによっては詳細設定内）にデバッグモードを切り替えるオプションが用意されている場合はそれを使う。ただし常時ONに固定すると本番データが汚染されるので、**GTM変数（例：Previewモード判定用の組み込み変数や、URLクエリパラメータ／特定ホスト名を参照するカスタム変数）で条件分岐させ、意図したときだけONになるようにスコープする**のが安全。固定値のON/OFFで本番タグに紛れ込ませないこと。

いずれの方法でも、本番公開前に該当パラメータ/チェックボックスを外し忘れないこと。

## 3. 採点パネル（このラボのground truth）

画面右下に浮かぶ「採点パネル (n/18)」が、このラボの正式な合否判定。GTM PreviewやGA4 DebugViewが「見た目それらしく動いている」と示していても、パラメータ名・型・発火回数・タイミングウィンドウの厳密な条件を満たさなければ採点パネルはFAILを返す——これが最終判定だと考えてよい。

- パネル上部のチャレンジ一覧が現在ページの課題ごとのPASS/FAIL/…（判定待ち）を表示する。
- 「Hit Log」欄に、実際に送信された（と傍受された）ヒットが新しい順に並ぶ。各行をクリックすると、正規化済みのJSON（`event`, `params`, `page`など）が展開表示される。

### 重要：Hit Logはページ再読み込みでリセットされる

Hit Logはメモリ上の配列で、ページ遷移・リロードをまたいで保持されない（これは意図的な仕様で、Lv4の「二重計上検出」系課題——例えばL4-01の「F5リロードしても`purchase`が再送されないこと」——を成立させるための前提になっている）。

つまり、タグが発火した**その場のページロードで**Hit Logを確認すること。一度リロードしたり、他ページへ移動してから戻ってきたりすると、直前のロードで実際にヒットが飛んでいたとしても、Hit Logは0件から再スタートする。「さっき飛んだはずなのにHit Logが空」と焦ったら、まずリロードを挟んでいないか疑う。

## トラブルシューティング

**Tag AssistantのウィジェットとLabGraderの採点パネルが重なって見えない**
どちらも画面右下に表示されるため、Preview接続中は重なって隠れがちになる。対処は2通り。
- Tag Assistantウィジェットの小さい折りたたみ矢印（⌄）をクリックして最小化する。**「終了」ボタンは押さないこと**——あれはデバッグセッションを終了するボタンで、タブが閉じることもある。
- DevToolsのConsoleで採点パネルを前面に出す：
  ```js
  document.querySelector('.lg-panel').style.zIndex = 2147483647;
  document.querySelector('.lg-panel').style.right = '420px'; // Tag Assistantウィジェットの幅ぶん左へ寄せる
  ```

**一番確実なのはDevTools Console**
UIの重なりや見た目のちらつきに振り回されたくないときは、まず `window.LabGrader.getHits()` をConsoleで実行する。捕捉済みヒットの生配列がそのまま返るので、パネルの表示崩れやスクロール位置に関係なく実際の送信内容を確認できる。トラブルシューティングの第一手として使うとよい。

**GTM PreviewのURLから`?gtm_debug=...`が消えている**
接続中のURLには`gtm_debug`クエリパラメータが付いている。何らかのリロードでこのパラメータが外れたプレーンなURLに着地すると、デバッグセッションが切断されている可能性が高く、Tag AssistantのデバッグコンソールもGA4 DebugViewも更新されなくなる。この状態はTag Assistant側で「接続されていません」と表示されるので気づける。プレーンなリロードだけでは接続は復活しないので、GTM側の「プレビュー」ボタンから再接続すること。

**一度だけ二重発火してしまい、修正後も同じ課題がFAILし続ける**
「このページをリセット」ボタンは、そのページの課題の進捗（`labgrader_progress_v1`）に加えて、セッションをまたぐ重複検出の状態（`labgrader_sent_ids_v1`）もあわせてクリアするようになっている。GTM設定のミスで`purchase`や`generate_lead`が一度だけ二重送信され、以後は正しく1回だけ発火するように直したのに二重計上FAILが消えない、という場合は、まず「このページをリセット」を押してから再テストすること。
